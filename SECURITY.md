# Security & Intellectual Property Policy

Thank you for visiting **Medical Admission Tracker**! We take security and the protection of intellectual property very seriously. 

Please read this policy carefully regarding the security of our application, reporting vulnerabilities, and the strict guidelines surrounding our intellectual property rights.

---

## 1. Strict Intellectual Property (IP) Rights

All rights, titles, and interests in and to **Medical Admission Tracker**—including but not limited to the codebase, system design, data schema, content structure, user interface, brand assets, and custom features—are strictly protected under intellectual property laws.

### Terms of IP Usage:
* **No Unauthorized Redistribution:** You may not copy, reproduce, distribute, or create derivative works from any part of this platform without prior written consent from the copyright holder.
* **Non-Commercial Use:** The provided materials, questions, and curated content on this platform are for personal educational use only. Commercial exploitation, scraping, or automated extraction of question sets or data for commercial platforms is strictly prohibited.
* **Proprietary Content:** Original content, custom metadata, explanations, and categorized question databases generated or compiled for this project remain the exclusive intellectual property of the repository owner.

---

## 2. Reporting Security Vulnerabilities

We appreciate the efforts of security researchers and developers in keeping the web safe. If you discover a security vulnerability or data leak associated with this project, please report it responsibly.

### How to Submit a Vulnerability Report:
Please **DO NOT** open a public GitHub issue for security bugs. Instead:
1. Contact the project maintainer via email or private channel (e.g., via GitHub Profile contact details).
2. Provide a clear description of the vulnerability, including steps or code snippets to reproduce the issue.
3. Allow us reasonable time to investigate and fix the issue before disclosing it publicly.

### Responsible Disclosure Guidelines:
* **Do no harm:** Avoid actions that could interrupt service or compromise user privacy/data integrity.
* **Privacy first:** Respect user data and do not attempt to access or extract sensitive information.
* **Public Disclosure:** Please keep any identified vulnerability confidential until a fix has been deployed.

---

## 3. Web Scraping & Automated Data Extraction

* Automated scraping, crawling, or mining of the question databases or site APIs without explicit authorization is strictly forbidden.
* Any unauthorized scraping or automated requests that violate our host environment (GitHub Pages) or attempt to bypass rate limits will result in immediate IP restriction or legal notice where applicable.

---

## 4. Updates to This Policy

We reserve the right to update or modify this security and IP policy at any time. Any changes will be published directly in this document (`SECURITY.md`).
