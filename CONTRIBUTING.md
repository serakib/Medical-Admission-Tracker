# Contributing

Thank you for your interest in improving Medical Admission Pro.

## Before making a change

- Check the existing issues and documentation to see whether the problem or idea has already been discussed.
- For a substantial change, open an issue first and wait for maintainer feedback before investing time in implementation.
- This repository is maintained with review and access controls. Please request maintainer approval before opening a large or unrelated change.

## Reporting issues

Use the repository's issue forms:

- **Bug report** for a reproducible defect.
- **Feature request** for a proposed improvement.
- **Accessibility issue** for a barrier involving keyboard use, assistive technology, contrast, motion, zoom, or layout.

Provide clear steps and relevant environment details. Never include passwords, authentication tokens, private student records, or other sensitive information in a public issue.

**Security vulnerabilities must not be reported through public Issues.** Follow [SECURITY.md](./SECURITY.md) and use a private reporting route.

## Pull requests

- Keep each pull request focused on one related change.
- Explain the reason for the change and link the related issue when one exists.
- Include testing details. Be clear about checks that were not run.
- Update documentation when behaviour, setup, or contributor expectations change.
- For user-interface changes, include screenshots when they help reviewers understand the result.
- Review the checklist in the pull request template before submitting.

## Project standards

- Follow the [Code of Conduct](./CODE_OF_CONDUCT.md).
- Follow [ACCESSIBILITY.md](./ACCESSIBILITY.md), especially for keyboard operation, visible focus, form feedback, reduced motion, responsive layout, and Bangla text.
- Follow [SECURITY.md](./SECURITY.md) when handling credentials, student data, and vulnerability reports.

## Scope and review

Medical Admission Pro is focused on the Bangladesh HSC (Class XI–XII) and medical-admission preparation experience. Changes should preserve the project's educational purpose, existing user data, and established behaviour unless the issue explicitly proposes a change.

All contributions are subject to maintainer review. A pull request may require revisions before it can be merged.
