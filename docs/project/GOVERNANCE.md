# Project Governance

## Current model

Medical Admission Pro is currently a maintainer-led project. The repository owner, **Rakib Hasan (@serakib)**, is the project maintainer and has final responsibility for project direction, repository access, releases and decisions about changes.

There is no elected committee, steering group or formal voting process at this stage. This document describes the current arrangement; it does not imply that additional maintainers or reviewers have been appointed.

## How decisions are made

The maintainer considers the project's educational purpose, student safety and privacy, accessibility, reliability, maintainability and compatibility with existing user data.

- Bug fixes are prioritized by impact, reproducibility and risk.
- Feature proposals should explain the student need and expected behaviour.
- Changes affecting accounts, scoring, rankings, rewards, privacy or backend data require particular care and may be deferred until they can be reviewed safely.
- The maintainer may request clarification, tests, documentation or revisions before accepting a contribution.

## Contributions and review

Read [CONTRIBUTING.md](./CONTRIBUTING.md) before proposing changes. All pull requests require maintainer review and are not automatically accepted. A pull request does not grant repository write access or permission to deploy backend changes.

The [Code of Conduct](./CODE_OF_CONDUCT.md) applies to project spaces and interactions.

## Releases and urgent fixes

The maintainer controls release decisions and publication. Release preparation follows [docs/RELEASING.md](./docs/RELEASING.md). Security issues must be reported privately as described in [SECURITY.md](./SECURITY.md); they should not be discussed in public issues before coordinated disclosure.

## Changes to governance

The maintainer may revise this governance model as the project grows. Any future maintainers, delegated responsibilities or decision-making process should be documented here explicitly.
